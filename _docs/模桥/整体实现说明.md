# 模桥 ModelBridge 整体实现说明

版本：v0.1.4；日期：2026/10/21。

## 1. 交付范围

Windows 本地桌面工具，中文界面。可刷新 OpenAI、Claude、Gemini、DeepSeek 官方模型名称，登录 Sub2API 读取当前账号全部 API Key，选择连接及模型，预览后追加到 Codex，并手动恢复本工具备份。

只发现名称的未知模型不会获得猜测参数。完整参数来源是当前 Codex 目录、本机内置目录、所选 Key 对应的站点 Codex 目录、显式导入的完整目录。参数已就绪不代表上游推理已验证。

## 2. 运行与文件布局

交付目录为 `D:\tools\sub2api-tools\CodexModelBridge`，源码在其 `source` 子目录。

| 文件或目录 | 作用 |
| --- | --- |
| CodexModelBridge.exe | 主程序，内含 Python 运行环境及网页资源 |
| runtime/ModelBridge.Key.exe | 内部 Windows DPAPI 凭据读取助手，由 Codex 自动调用，用户无需单独打开 |
| sources.json | 可编辑的官方来源、域名、提取规则和模型名称前缀 |
| 使用说明.md | 普通用户使用步骤及源码构建方法 |
| data/settings.json | 站点地址及 Codex 路径，不包含 Key |
| data/official-models.json | 当前官方目录结果与新发现标记；baselines 保存各来源最后一次成功的比较记录 |
| data/secrets/*.bin | 当前 Windows 用户加密的选中 Key |
| data/backups/*.bin | 当前 Windows 用户加密的配置备份 |
| Codex 配置目录/modelbridge/*.json | 每次应用的新模型目录，不覆盖旧目录 |

依赖 Windows 10/11、WebView2、本机 Codex。单实例桌面窗口默认 1280×860，最小 980×700。运行不要求管理员权限，不要求用户安装 Python。移动交付目录后需要重新应用连接，更新 Codex 中凭据助手的绝对路径。

## 3. 模块职责

| 模块 | 实现职责 |
| --- | --- |
| main.py、bridge/desktop.py | 本地入口、单实例、独立站点窗口、登录来源校验 |
| bridge/server.py | 回环 HTTP 服务、静态文件白名单、会话令牌与来源校验 |
| bridge/service.py | 登录代次、Key 选择、操作互斥、方案失效与设置 |
| bridge/sub2api.py | 当前用户、完整密钥分页、网关模型目录 |
| bridge/discovery.py、bridge/catalog.py | 官方名称提取、参数来源合并和精确模型匹配 |
| bridge/codex.py | 配置解析、保留合并、真实解析器校验、应用及恢复 |
| bridge/storage.py、credential_helper.cs | 原子文件写入、摘要和 Windows DPAPI |
| web/ | 中文页面、筛选、选择、预览、设置和备份 |

厂商卡片的筛选按钮和官方资料按钮为并列元素，不嵌套交互控件。卡片及“全部模型”调用 selectProvider，同步选中样式和 aria-pressed，仅重绘模型列表；四家重复标签已移除。保留搜索词、勾选集合和筛选按钮焦点。搜索框宽窗口最多 420 像素、高度 42 像素，窄窗口独占一行；SVG 图标居中且忽略鼠标事件。厂商信息来自来源配置，不增加固定映射。

select-key 在原有互斥锁内校验选择并调用 _read_station，refresh-station 复用同一路径。两者返回 count/error，state 提供 station_checked、station_error、station_count；选择成功但读取失败仍保留新 key_id，同时清除旧 remote 目录及旧预览。前端显示加载状态、失败原因和显式重试，不自动重试或补造参数。

参数处理弹窗复用 import-catalog 的校验路径，根据登录、Key、读取错误和该模型是否已就绪提供下一步；导入后更新当前弹窗，可直接选中模型。两组文件输入共用 importCatalog。新增网络提交继续使用 action 的 busy 门闩；单纯定位输入框不启用提交锁，以保证焦点可落到目标。

Discovery.refresh 读取成功比较记录，旧版缓存中同 URL 的成功结果迁移为初始记录。新记录包含完整来源配置和模型名，来源配置改变时重新建立基线。当前成功结果保存 new_models、comparison_available，失败结果模型为空且单独保留基线；Catalog.rows 输出 is_new 并稳定前置。数据通过一次 write_json 原子保存，不向界面暴露历史基线冒充当前模型。

底部两项单选最终仍映射既有 prepare.activate 布尔值。默认、换 Key 和应用成功后恢复只添加；选 Key 不再自动启用 activate。主页面、预览标题、连接变化行、确认按钮都明确本次是否切换及目标站点/密钥；Key 仅展示掩码。

## 4. 外部契约与请求示例

外部接口遵从 Sub2API 约定，本地业务接口统一采用 POST 和中划线名称。没有业务数据库、字典表、菜单权限配置和 SQL 变更。来源厂商为 sources.json 中的可编辑集合；站点状态值直接按上游协议使用。

| 操作 | 外部契约 | 认证 |
| --- | --- | --- |
| 站点登录 | 在站点 `/login` 页面完成，读取准确同源 localStorage 的 auth_token | 站点原有登录方式 |
| 当前用户 | GET /api/v1/auth/me | 登录 Bearer Token |
| 全部密钥 | GET /api/v1/keys?page=1&page_size=100，继续遍历至 total | 登录 Bearer Token |
| Codex 目录 | GET /v1/models?client_version=本机版本 | 明确选中的 API Key |

管理响应要求 `{ "code": 0, "data": ... }`；密钥分页要求 data.items、data.total；模型响应要求 `{ "models": [完整的 Codex 模型条目] }`。所有账号、密钥、分组 ID 返回网页前转字符串。认证请求禁止跳到其他来源；官方资料请求只允许来源配置中的 HTTPS 域名。

站点地址支持 HTTP、HTTPS。begin_login 通过 site_from_input 在输入边界识别末段 /login、/keys（允许末尾斜杠），去掉对应页面的查询参数和锚点，保留协议、端口和前面的部署路径。Sub2Api 内部继续调用 normalize_site 校验已经确定的入口，不重复解析页面路径。start-login 返回实际 site，前端立即回填，后续登录及数据请求复用该入口。未知路径不自动删除，也不自动探测其他入口。地址输入框下方实时显示 HTTP 未加密提示，不增加确认弹窗或阻止登录。HTTPS 证书仍由系统正常校验；允许 HTTP 站点不会放开官方资料的域名限制，也不会自动跟随携带认证的跨来源重定向。

本地预览示例：`POST /api/prepare`，内容为 `{ "models": ["准确模型ID"], "activate": true }`；随后 `POST /api/apply` 使用预览返回的 plan_id。只有正确的 Host、Origin 和本次运行随机 X-Bridge-Token 才能访问。静态页面不会暴露该令牌；首次桌面 URL 通过 fragment 传入，页面随即移除 fragment。

## 5. Codex 写入与恢复

使用 tomlkit 保留注释与其他配置。现有模型按 slug 去重且原样保留；明确新增的模型 visibility 设为 list，能力参数来自原目录。默认模型不变。当前 profile 覆盖模型目录或待切换连接时停止应用。

读取本机 `codex debug models --bundled` 获取内置参数。在隔离 CODEX_HOME 中调用 `codex debug models -c model_catalog_json=...` 校验目录和候选配置；不调用推理接口。

应用新连接时写入 model_providers.modelbridge，使用站点 `/v1` 地址和 responses 协议。凭据使用官方 auth.command，指向 `runtime/ModelBridge.Key.exe` 和加密凭据路径，不把新 Key 写入配置明文。该提供商配置作用于后续使用它的 Codex 请求，原模型能否调用由 Key 的分组权限决定。

先保存加密备份，再写新目录与加密 Key，最后替换 config.toml。预览和替换前比较原配置及原目录摘要；发现外部修改即停止。方案一次性消费，操作由锁串行。恢复要求备份归属同一 Codex 目录，并比较当前配置摘要；恢复前也备份。版本目录和旧凭据保留以支持恢复，不自动清理。

- 四家官方来源实际联网刷新均成功；本次候选数分别为 4、4、10、4。数量仅为 2026/10/21 当次页面结果，不是长期固定值或服务可用性证明。
- 浏览器实际操作模拟站点：选择 Key、读取目录、搜索勾选、预览、应用，模型数由 1 变 2；恢复后回到 1。未出现页面控制台错误。
- 页面检查覆盖默认桌面尺寸和 980×700 最小尺寸；主操作可见，其余内容可滚动。
- 打包程序在隔离数据目录启动成功，主进程、回环页面服务和 WebView2 子进程正常运行，页面返回 HTTP 200。

验证边界：以上写配置操作仅针对 source/work 下隔离目录。未修改用户真实 Codex 配置；未登录真实 Sub2API 站点；未发送推理请求。目标站点的验证码、OAuth、二次验证、定制接口、真实分组路由仍须登录后验证。官方网页结构变化时须更新来源配置；不会自动改走其他未配置来源。

初次开发时，按 pr-review-local-git 的要求对新建仓库的完整新增文件进行本地审查；当时没有远端和历史提交，不冒充远端 PR 审查。GitHub 首次发布沿用远端初始化提交，检查 origin/main 与待发布内容的差异。审查结论及修正项见月度记录。

v0.1.1 更新前核对：用户当前 Codex 配置未引用外层旧凭据助手，工具没有配置备份，因此此次归档旧文件不会切断现有凭据路径。仅修改程序文件，保留用户 data 和 sources.json。其他已应用旧版本的安装目录升级时，需要先处理现有配置及备份中的旧助手引用；不得直接移动其仍在使用的文件。
